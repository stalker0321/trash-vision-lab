## Воспроизведение

Для повторной сборки замороженной D3 нужны manifest из репозитория и reviewed-пул
с исходными изображениями и labels. Исторические обучения для этого не нужны:

```bash
python3 -m datasets.build_d3 --from-manifest \
  --reviewed-root /path/to/trash-vision-dataset \
  --manifest manifests/d3.json \
  --output data/versions/d3
```

Проверяются fingerprint manifest, группы/splits, хеши исходных и полученных
изображений и labels. Исходники используются только для чтения; результат
содержит независимые копии. Существующая версия не перезаписывается.
Для текущего frozen D3 все source image bytes уже совпадают с нужными oriented
bytes. Если будущему manifest понадобятся отдельные EXIF-нормализованные копии,
сборщик явно потребует `--baseline-root`.

Чтобы повторить первоначальный freeze и аудит изменений относительно D2,
дополнительно нужен исторический training workspace с baseline manifest/labels:

```bash
python3 -m datasets.build_d3 \
  --baseline-root /path/to/trash-lab-dataset-v2 \
  --reviewed-root /path/to/trash-vision-dataset \
  --manifest manifests/d3.json \
  --output data/versions/d3
```

Для проверки повторного получения того же manifest без копирования изображений:
та же команда с `--plan-only`. Замороженный manifest нельзя молча заменить
другим содержимым. Метки воспроизводятся из reviewed-пула с проверкой хешей.

## Обучение

Рецепт: `configs/d3_training.json`. Оба запуска — seed42, 150 эпох, batch16,
AdamW, WD=0.001; остальные параметры совпадают с сентябрьскими D2/wd001.
Стартуют с тех же исходных pretrained weights, проверяемых по SHA256.
Сравнения: `yolo26n_d2_s42_wd001` и `yolo26m_d2_s42_wd001`.
Это одна пара на модель; она не даёт оценки разброса между seed.

Нужно отдельное рабочее окружение Python 3.12 / torch 2.8.0 /
Ultralytics 8.4.143 с совместимым torchvision. Историческое локальное окружение
повреждено RKNN-зависимостями; его нельзя считать готовым для обучения.

В отдельном Python 3.12 окружении зависимости восстанавливаются командой:

```bash
python scripts/bootstrap_training.py
```

Она использует `configs/requirements-training-linux.lock` и CUDA 12.8 wheels
torch 2.8.0 / torchvision 0.23.0. Этот lock также проверен в отдельном Windows
окружении MSI. GPU-драйвер должен поддерживать указанную версию CUDA.

Проверка плана без ML-зависимостей:

```bash
python3 -m runners.train_d3 --model yolo26n --weights-root /path/to/weights --plan-only
python3 -m runners.train_d3 --model yolo26m --weights-root /path/to/weights --plan-only
```

После подготовки окружения/GPU: сначала каждую команду с `--smoke` вместо
`--plan-only` (одна эпоха на 128 train / 64 val), затем полные запуски:

```bash
python3 -m runners.train_d3 --model yolo26n --weights-root /path/to/weights --device 0
python3 -m runners.train_d3 --model yolo26m --weights-root /path/to/weights --device 0
```

Запускать последовательно с проверкой успешного завершения каждой команды.
`--resume` продолжает совместимый прерванный запуск. Существующие завершённые
runs не перезаписываются. Проверяются хеши данных до и после обучения;
image verifier сохраняет корректные JPEG с хвостовыми данными без перезаписи.
Перенесённые на другую машину данные получают новые абсолютные списки
изображений внутри run, поэтому пути от локальной сборки не используются.

## Проверка и границы результата

Проверены все входные/выходные image hashes при сборке и геометрия labels.
Прошли восемь unit tests (изменение source/labels, утечки групп, catalog в holdout,
границы боксов, независимые копии, защита от перезаписи, сборка по manifest без
исторического workspace и отклонение изменённого manifest), dummy smoke и оба
`--plan-only`. GPU smoke Nano прошёл, полное обучение продолжается.
Окружение Medium проверено на RTX 3090; его GPU smoke выполняется после передачи данных.

Старые и новые checkpoints надо оценить на одной версии reviewed test;
сентябрьские метрики не переносить в новую таблицу без переоценки. Выбор эпохи,
порогов и кандидата для Pico — по validation. Исторические ограничения mining
на общем real-пуле сохраняются. Таксономия D0/D1 разобрана в `taco-provenance.md`.

Общая оценка любого сохранённого четырёхклассового checkpoint:

```bash
python -m runners.evaluate_d3 \
  --weights /path/to/best.pt --imgsz 320 --split test \
  --output runs/evaluation/nano_d3_test --device 0
```

Для Medium используется `--imgsz 640`; доступны `val`, `test`, `hard_test`.
Выходная директория должна быть новой. `--plan-only` показывает протокол и хеши
без ML-зависимостей. Оценка проверяет frozen manifest, порядок классов и хеши
выбранных данных до и после inference. Сохраняются общий и поклассовый AP,
predictions, матрицы ошибок, версия окружения и SHA256 весов.

Параметры оценки фиксированы: batch8, conf=0.001, IoU=0.7, max_det=300,
FP32, без test-time augmentation. Это протокол расчёта AP, а не рабочий порог
для Pico. Скорость validator не считается сравнительным бенчмарком устройств.

# D3: reviewed annotations on the frozen D2 splits

D3 preserves the selected D2 images, groups and split membership, and replaces
the earlier annotations with the retained reviewed labels. The materialized
version is excluded from Git and is rebuilt from `manifests/d3.json`.

Nano320 completed on the MSI RTX 4060 laptop; Medium640 completed on a
Vast RTX 3090. Both ran all 150 epochs. The [final common-holdout report](../reports/d3/README.md)
includes all 12 evaluations and the complete training records. Historical
D0/D1/D2 datasets and checkpoints are retained; see the [baseline policy](retraining-plan.md).

A network outage interrupted Medium after epoch 122. Training resumed with
optimizer state restored and the same recipe; its data/augmentation order
need not match an uninterrupted run. Metadata records the interruption and
sums elapsed training time across attempts. The raw CSV time column restarts
at resume, while its epoch column remains the complete sequence 1–150.

## Rebuild the frozen version

Use the committed manifest and the reviewed source pool. Historical training
runs are not needed for this route:

```bash
python3 -m datasets.build_d3 --from-manifest \
  --reviewed-root /path/to/trash-vision-dataset \
  --manifest manifests/d3.json --output data/versions/d3
```

The builder checks the manifest fingerprint, group/split separation, and the
source/output image and label hashes. It reads source data without modifying
it and refuses to overwrite an existing output directory.

For the current D3, source image bytes already equal the required oriented
bytes. A future manifest requiring separate EXIF-normalized copies will
explicitly require `--baseline-root`.

To repeat the original freeze and compare label changes against D2, also
provide the historical workspace containing its baseline manifest/labels:

```bash
python3 -m datasets.build_d3 \
  --baseline-root /path/to/trash-lab-dataset-v2 \
  --reviewed-root /path/to/trash-vision-dataset \
  --manifest manifests/d3.json --output data/versions/d3
```

Add `--plan-only` to verify that the same manifest is reconstructed without
copying images. A different manifest cannot silently replace the frozen one.

## Train Nano and Medium

The [recipe](../configs/d3_training.json) fixes seed42, 150 epochs, batch16,
AdamW and weight decay 0.001. It preserves the September D2/WD=0.001 settings
and starting pretrained checkpoint hashes. The comparators are
`yolo26n_d2_s42_wd001` and `yolo26m_d2_s42_wd001`. One seed per model does not
estimate run-to-run variation.

Use a dedicated Python 3.12 environment with CUDA-capable hardware:

```bash
python scripts/bootstrap_training.py
```

The bootstrap installs the pinned environment from
`configs/requirements-training-linux.lock`, including PyTorch 2.8.0,
TorchVision 0.23.0 CUDA 12.8 wheels and Ultralytics 8.4.143. This lock also
passed installation and GPU smoke checks on Windows. The GPU driver must
support that CUDA runtime. Keep RKNN export dependencies in a separate venv.

Check the plans without importing ML dependencies:

```bash
python -m runners.train_d3 --model yolo26n --weights-root /path/to/weights --plan-only
python -m runners.train_d3 --model yolo26m --weights-root /path/to/weights --plan-only
```

After environment setup, replace `--plan-only` by `--smoke` for one epoch on
128 training / 64 validation images. Then launch the full runs:

```bash
python -m runners.train_d3 --model yolo26n --weights-root /path/to/weights --device 0
python -m runners.train_d3 --model yolo26m --weights-root /path/to/weights --device 0
```

On one GPU, run these sequentially and check each command's exit status.
These parallel runs used separate machines. Medium640/batch16
used about 12 GB VRAM during training, so this recipe is not suitable for
an 8 GB card unchanged.

`--resume` continues a compatible interrupted run. Completed/existing runs
are not overwritten. Image/label hashes are checked before and after training.
The image verifier decodes valid JPEGs with trailing bytes without rewriting
them. Absolute image lists are regenerated per run, making transferred bundles
independent of paths on the machine that built D3.

## Common-holdout evaluation

Evaluate historical and new checkpoints against the same reviewed annotations.
Historical validation scores must not be copied into this new comparison.
Epoch selection and threshold experiments use validation, not test.

```bash
python -m runners.evaluate_d3 \
  --weights /path/to/best.pt --imgsz 320 --split test \
  --output runs/evaluation/nano_d3_test --device 0
```

Use `--imgsz 640` for Medium. Available splits are `val`, `test`, `hard_test`.
The output directory must be new; `--plan-only` prints the protocol and hashes
without loading ML dependencies. The evaluator checks the frozen manifest,
class order and selected input hashes before/after inference. It saves overall
and per-class AP, predictions, confusion plots, environment and checkpoint SHA256.

The fixed protocol is batch8, conf=0.001, IoU=0.7, max_det=300, FP32 and no
augmentation. This is an AP evaluation protocol, not the Pico operating threshold.
Validator timing is not a controlled deployment speed comparison.

The [evaluation queue](../configs/d3_evaluation.json) fixes four checkpoints ×
three splits. Once all 12 summaries are present:

```bash
python scripts/summarize_d3.py --root runs/evaluation --output reports/d3 --plot
```

Plotting additionally requires Matplotlib. The summary rejects incomplete
queues, different weights between splits, changed image/box populations and
protocol mismatches.

## Model artifact archive

After both runs, the Nano export and the common-holdout report are complete,
package the models separately from Git:

```bash
python scripts/package_d3.py \
  --nano-run runs/d3/yolo26n_d3_s42_wd001 \
  --medium-run runs/d3/yolo26m_d3_s42_wd001 \
  --nano-export runs/export/d3-nano \
  --report reports/d3 --output dist/trash-vision-d3-seed42.tar.gz
sha256sum -c dist/trash-vision-d3-seed42.tar.gz.sha256
```

The report directory must contain the 12 source summaries under `inputs/`,
as in the published report. The packager verifies all 150 epochs, completed
training records, checkpoint/export hashes and evaluation provenance. It
includes both best checkpoints, Nano ONNX/RKNN, configuration, training CSVs,
evaluation summaries and an internal checksum manifest. It verifies the
archive again before publishing the local file and refuses overwrites.
Dataset images and calibration copies are excluded. The `dist/` directory
is ignored; large model artifacts belong in a release or external artifact
store, separately from the source repository.

## Checks and interpretation

Eight lightweight dataset tests cover source mutation, group/catalog leakage,
box boundaries, independent output copies, overwrite protection and manifest-only
reconstruction. They passed on Linux and Windows. The dummy training smoke,
training plan checks and both real GPU smokes also passed.

D3 changes labels while retaining D2 images, but historical D2 best checkpoints
were selected using older validation labels. Historical mining/review involved
the wider real-image pool, and recovered groups cannot prove every related
capture sequence was identified. The comparison is therefore a retrospective
common-holdout evaluation, not a perfectly isolated annotation-only experiment.
See [TACO provenance](taco-provenance.md) and [project history](project-history.md).
